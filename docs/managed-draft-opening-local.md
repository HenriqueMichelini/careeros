# Local complete-Draft opening

This is the explicit synthetic implementation of [#285's selected protocol](https://github.com/HenriqueMichelini/careeros/issues/285#issuecomment-6644976301). The [frozen interface and race table](application-draft-opening-contract.md) distinguish readiness, complete opening, human review/Accept, customer allowance and provider exposure.

`draftrecovery.OpenLocalOpening` requires the private disposable PostgreSQL schema/loopback boundary, controlled provider/reviewer and existing shared Action authority. It composes the actual activated pilot grant with additional restrictive injected decisions. It never substitutes SYN laboratory units or supplied Delivered flags for real finite-five grant/settlement authority. Ordinary controlled, managed and Function compositions are unchanged; the combined path remains unactivated until #286 integrates terminal resolution.

The repository reserves one real pilot right in the same transaction as the generation witness, before its callback can execute. Reservations/deliveries count across namespaces for the owner, so changing namespace does not reset the five-right limit. The independent authenticated runtime/reconciliation roles cannot read/write allowance or receipt tables, and runtime raw SQL debit/release remains denied. The purpose repository owns only its bounded customer transition; no operator/customer override endpoint exists.

`GET /api/draft-allowance` reports the fixed total, held, consumed and remaining rights. It resolves elapsed/terminal existing holds under the current authority without inference. Its separate metadata path does not shadow `/api/drafts/{creationKey}`.

Opening receipt issuance and confirmation are authenticated POST operations on the exact version. The issued identifier/HMAC binds owner, namespace/shared Action, exact bundle digest/complete manifest, current session and policy. The record exists before reply. Identical issuance after a lost reply recovers the same receipt; a different session obtains a different receipt for the same result. The immutable customer row binds original pilot activation/expiry and original admission/deadline. Exact content and its completed support snapshot are revalidated. A partial/mixed manifest or forged/wrong-owner/session/version receipt has no effect.

The normal UI presents an opening entry for undelivered ready work. Deliberately opening it mounts the actual review; after commit, the app checks the exact article and all required artifact/support nodes, obtains the receipt, checks availability again, then automatically acknowledges that same opening. There is no optional charge button after normal complete review presentation. A missing required part, CSS-hidden part or hidden ancestor sends no acknowledgment. Collapsed expandable support remains available for review. Accept/export remain separate and cannot create another delivery. The receipt is not human-comprehension proof.

Account/session, grant and mutable settlement locks precede the final database clock. Confirmation is eligible only strictly before original admission plus 30 minutes and original grant expiry, with current source/deletion/cancellation rights. Resolving an older held outcome cannot let a new generation use pre-wait session/time. Profile changes before the first confirmation close stale pending work without consumption; changes after confirmation preserve its one effect and disclose the original historical snapshot. New/duplicate ACK and lost replies recover by GET; no automatic generation/retry is introduced.

Observed terminal closure releases a customer hold once, denies/queues undelivered purpose content and permanently prevents late consumption. Delivered rights are not refunded by cancellation or content cleanup. The provider dispatch, unknown expense and occupied scope slots are unchanged. The existing restore/A32 boundary and a separate older-purpose/customer-row test consume a non-restored injected terminal decision; they are not hosted restoration or an independently implemented surviving-authority service.

Verification includes actual pilot last-unit/cross-namespace/cross-tab races, both clock-lock waits, pre-generation expiry, terminal event ordering, lost receipt/ACK, raw SQL role denial, independent provider holds and real private fsync PostgreSQL crash/restart with a fresh server. Restart compares exact Result/receipt/allowance bytes and an append-only generation/check witness. Real EN/PT React→Vite→Go/PostgreSQL cells include controlled withheld support, lost committed confirmation reply, GET-only recovery and 401/403 protected hiding. No real grant, participant, provider account/call/spend, hosted operation, deployment or GitHub mutation is performed.
