# Durable Application Draft review contract v1

This freezes the local interface for [#284](https://github.com/HenriqueMichelini/careeros/issues/284) on cumulative base `e4fd48d2e425a3a7b1492a4263e00d130be4e98f`. It consumes #281's exact retained bundle and the selected [historical review/Accept](https://github.com/HenriqueMichelini/careeros/issues/284#issuecomment-6645202436), [historical export](https://github.com/HenriqueMichelini/careeros/issues/284#issuecomment-6644605240), and [opening order](https://github.com/HenriqueMichelini/careeros/issues/285#issuecomment-6644976301) contracts. It does not implement opening, allowance settlement or a new generation workflow.

The public seams are the existing authenticated Draft router/client and the actual React browser against local controlled Go/PostgreSQL. Generation and completion callback counts must not change during review, Accept, status or export. Production composition remains closed; no provider, participant, hosted or remote operation is authorized.

## Exact decisions and snapshots

Each immutable Action/version owns four artifact decisions: `summary`, `resume`, `cover`, and `answers` (including an explicit none-requested answer state). A human deliberately marks an artifact reviewed, then deliberately accepts that same artifact. Decisions bind the authenticated owner, Action, bundle version, published digest, artifact and expected review revision. They do not change generated wording, support evidence or Profile. The original bundle already passed its required support/completeness checks; human approval is not a new machine-support claim.

`POST /api/drafts/{key}/versions/1/review` accepts only a bounded command with a stable decision key, exact published digest, artifact, `review`/`accept` operation and expected review revision. Server-owned accepted state can arise only from a valid current decision on an already authoritatively delivered complete bundle. Readiness, GET, browser flags and Accept cannot create delivery. A repeated decision key with identical bytes recovers its existing effect; changed content conflicts. A new stale expected revision cannot apply to a different artifact/version. The original Action/version remains immutable even after another candidate exists.

The existing exact-version GET returns current per-artifact decisions. Once all four artifacts are explicitly accepted, the same exact immutable bundle is an accepted snapshot. `GET /api/drafts/accepted` retrieves the most recently completely accepted authorized snapshot; it never promotes a partially accepted or new/failed candidate. The exact-key GET remains available for an intentionally selected historical snapshot. No extra generated career content is retained: review state and decision bindings reference the existing purpose-owned complete bundle. Purpose cleanup removes its decisions too, retaining independent non-content expense/replay protection.

## Authority and currentness

All decision writes serialize using existing account/session, injected authority and Action/content locks. Recheck trusted time and read/delivery/deletion fences after blocking work and before commit. Response bytes and export retrieval remain under the final read fence through the outer account router write. Lost-write acknowledgment recovery reads the same persisted decision and bundle without inference.

An already delivered snapshot may be reviewed, accepted and exported after Profile changes, with original Profile ID/revision and an explicit historical warning. No fresh-support claim is made. A source change before first confirmed opening closes undelivered work under the injected selected opening contract; #285 supplies its actual opening/settlement implementation separately. Current read/retrieval rights, the original post-grant window and deletion fences still win. Temporary read denial withholds every protected browser copy without deleting the stored snapshot or opaque recovery key. Foreign account changes cannot inherit another owner's input or results.

Display, copy and PDF use the chosen accepted snapshot and frozen identity/signature, never today's Profile or a newer candidate. All export forms disclose the original version/revision and historical state. PDF uses existing local layout, clipping and overflow protections; clipboard failure stays explicit and keyboard focus is preserved. Legacy Results currentness is tested with two synthetic tabs under #135 before classifying any #136 condition; unconfirmed hypotheses are not defects.

Verification freezes independently expected review revisions/content, lost-ack and concurrent decision outcomes, process/PostgreSQL restart, identity/version/account negatives, and actual EN/PT desktop/390px keyboard/copy/PDF results. Local synthetic results are not hosted readiness or live model-quality evidence.
