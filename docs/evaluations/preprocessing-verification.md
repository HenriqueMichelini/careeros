## Contract evidence

- Source tests assert deterministic representation, idempotent prepared text,
  ordered contiguous mapping/segment coverage, valid UTF-8 endpoints and exact
  original-excerpt recovery. Every occurrence remains addressable; identical
  text under different contexts retains separate IDs. Invalid/partial/reversed,
  out-of-bounds and split normalization-group requests fail explicitly.
- Bounds tests exercise 30,000/30,720 decoded bytes, 160/128 KiB HTTP bodies,
  multibyte crossings, NFC expansion, JSON overhead, exact final-payload limits,
  protected blocks, ancestor overhead and portion exhaustion. Portions plus
  unprocessed ranges partition the original; a multi-portion complete plan is
  still insufficient for the current single-view workflows. Nothing executes
  first-N portions or silently truncates; planned coverage is not discovered
  career facts.
- Profile ingestion's successful supported claim takes exactly one Jev plus
  extraction and comparison calls (three). Apply's two protected handlers each
  take one Jev plus one downstream call (two). Preparation adds zero calls.
  Controlled transports inspect complete original Jev submissions and complete
  prepared extraction/job text. Profile comparison intentionally receives the
  recovered original claim excerpt, preserving the existing evidence contract.
- Rejected, rephrasing, invalid classifier output, outage, timeout and capacity
  cases make zero downstream calls. Strict schemas reject forged `accepted`,
  `decision`, `prepared` and `sourceMap` fields. A prepared artifact never grants
  acceptance. Preparation is pure; Profile prepares before Jev, Apply after Jev,
  and both gate all downstream execution on the whole original decision.
- Success handlers assert `Cache-Control: no-store`; existing decision tests
  cover failure no-store. Log capture asserts no raw/prepared submission,
  source identifier or synthetic credential leakage. Classifier projection is
  only field and complete submission; downstream projections retain existing
  task data. Only supported claim excerpts and occurrence references are returned
  by ingestion, never the complete source map or source representation. Review
  proposals remain transient; only explicit existing Profile apply writes persist.
- Browser assertions preserve original text and saved Profile on failure,
  cancellation, changed original and unapproved proposals. Review renders exact
  original whitespace; changing raw formatting invalidates proposals even when
  prepared text would agree. Keyboard Tab/Enter correction and deliberate retries
  run in both languages/widths. Added multibyte byte-counter assertions admit
  15,000 `é` (30,000 bytes) and disable submission at 30,001 without truncation.

Visual inspection sampled Portuguese mobile source review and English desktop
Results; screenshots retained in `evidence/preprocessing/`. They show preserved
source whitespace and unknown employer feedback. Other locale/viewport behavior
is supported by browser assertions, not exhaustive visual review.

## Resources and deadline guards

Reference host: AMD Ryzen 5 3600, 6 cores/12 logical CPUs, Linux amd64. Benchmarks
are synthetic local preparation + repetition annotation + single-view planning,
including the test JSON serializer. They do not serialize each production prompt
or measure peak resident memory. B/op measures cumulative allocation, not retained
memory. Three samples are retained in `evidence/preprocessing/benchmarks.txt`.

| ---: | ---: | ---: | ---: | ---: |
| 120 | 105–107 µs | 30,680–30,698 | 5 | 1 |
| 6,000 | 6.30–7.01 ms | 2,082,192–2,088,772 | 285 | 1 |
| 30,000 | 65.99–67.56 ms | 14,215,571–14,252,416 | 1,429 | 1 |
| 30,720 (Job Posting) | 68.07–68.99 ms | 14,218,111–14,247,607 | 1,463 | 1 |

Each case has two repetition groups, retaining all their occurrences.

```sh
GOCACHE=/tmp/careeros-go-cache go test ./internal/preprocessing -run '^$' -bench BenchmarkWorkflowPreparation -benchmem -count=3
```

The package performs no I/O or recursive provider loop. Raw input caps, finite
mapping/segment/occurrence counts, protected atomic groups and portion budgets
bound admitted work. Existing 15,000-short-segment and expansion tests cover
adversarial shape independently of the prose/list benchmark. Measurements do
not establish linear scaling or worst-case timing. Production capacities may
reject a source fitting the raw limit when segment metadata exceeds 256 KiB.

Deadline source guards remain unchanged: Jev 3s; ingestion 52s parent / 24s
per downstream request; qualification checking and drafting 25s per downstream
request. Existing controlled deadline/failure tests pass. No provider latency,
token savings, cost savings or deadline improvement is inferred from benchmarks.

Live/deployed, broader migration/continuation, semantic quality and actual exported
artifact checks are unverified here and remain with #52 and their owning issues.
