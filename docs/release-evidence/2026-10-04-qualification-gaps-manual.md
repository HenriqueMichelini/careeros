The tester confirmed that the API key already configured in both browser origins was the dedicated OpenAI test key and authorized one billable qualification-gap request per origin. ## Exact outbound-payload preflight

Before either request, source review traced `findProfileGaps` through the Go handler and `openaihttp.Post`. The browser sends the complete Profile and posting to Go. The Go-to-OpenAI body contains only `model`, `reasoning_effort`, `max_completion_tokens`, `response_format`, and one user `messages` entry. That entry contains the posting and a JSON qualification projection with top-level fields `skills`, `competencies`, `tools`, `experience`, and `projects`. Experience entries contain `title`, `description`, `responsibilities`, `achievements`, and a derived `duration`; projects contain `description`, `technologies`, and `highlights`. The Profile projection excludes dedicated compensation, employment status, names, IDs, URLs, locations, career goals, additional information, experience dates, the `current` flag, and experience recency. The posting is sent as supplied. The key is in the outbound authorization header, not the body.

The fixture was synthetic in both browser origins: one fictional data-role experience, qualification text, empty project and tools sections, empty compensation and additional-information text, and a synthetic posting. The posting included qualifications clearly absent from the Profile, making a suggestion result likely and avoiding an automatic transition into Application Draft. The targeted allowlist and no-cache Go tests passed before the live calls. The deployed preview used the same Go handler as local HEAD; the published revision predates documentation-only commits and contains that handler as well. The preview had advanced beyond the matched-revision snapshot in [the release-test path](../release-test-path.md); `git diff 910d8ad..ed40373` shows no changes to the qualification handler, browser AI call, gap UI, or Netlify routes. This preflight checks the outbound construction and fixture fields, not a captured provider request body.
