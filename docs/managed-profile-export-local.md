# Local authenticated Profile Export

`GET /api/profile/export` is part of the existing authenticated account router and the explicit pilot composition, including the account Function alias. The Profile page offers EN/PT “Download Profile JSON”. It exports only the saved account-owned Profile, never local drafts, pending Save content or browser recovery data. The server envelope is `careeros-profile-export` version 1 with a complete Profile v2 document in `profile`; provenance is embedded in facts, evidence and typed links. No readable companion, import, new retained class, temporary export link or server export file is created.

The BYTEA document is copied verbatim into the envelope, including unknown qualifiers, normalization observations, IDs/revisions, excerpts, supported opaque structures and exact numeric lexemes. The browser parses a temporary copy only for envelope/version compatibility and downloads the original response Blob. It never stringifies that parsed copy; numbers beyond JavaScript safe-integer precision remain intact in the file. Neither this download nor an unknown state becomes an approval/support upgrade. Legitimate compensation and certification credentialId fields remain career data, not authentication credentials. Export does not join auth, invitation, allowance or restricted financial records into the package.

Ownership comes from the exact current server session. The account header is only a cookie-switch consistency condition. Query selectors are rejected. Account/session and pilot mutation locks stay held through the actual outer response callback. Trusted session time and PilotRetrieve are rechecked after the document read/encoding, immediately before writing. Pilot rights permit export during active access and the selected 30-day post-expiry window; revoked/suspended/expired rights deny it. No saved Profile yields404. Errors are content-free; client messages use fixed codes and do not display server diagnostic text. The file has a fixed safe attachment name, JSON content type, no-store and nosniff.

The user explicitly starts each export. The UI truthfully reports download initiation, not proof of a durable save in the user’s filesystem. Requests time out, old-owner responses are discarded after switch/unmount, and Blob URLs are revoked. No file content is stored in local/sessionStorage. Export is optional and never gates deletion. This implementation neither changes deletion timing nor implements the later deletion lifecycle.

All verification uses synthetic data, fake OIDC and a private disposable PostgreSQL instance. No provider call, actual participant/grant, deployment/configuration change, hosted recovery, push or remote issue change is authorized or performed. The browser fixture’s bootstrap/control endpoints exist only in a Go test binary, with a private capability token and loopback server. No production constructor installs them.
