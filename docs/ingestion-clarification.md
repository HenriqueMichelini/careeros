# Focused Profile clarification

Issue #42 adds an optional `clarification: {claim, answer}` request to the existing stateless ingestion handler. It is mutually exclusive with a continuation portion. The complete original input is validated again by the server-owned professional-information policy; a separate policy decision validates the selected statement, question, prior support and answer together. Neither a client acceptance flag nor an answer can replace validation of the original submission.

Semantic extraction receives only the selected statement, its supporting excerpts and the new answer. It produces one revised claim; invalid, skipped or multiple returned claims fail without replacing the pending review. Source excerpts keep their original references. Answer excerpts carry `origin: clarification_answer`, remain transient until explicit approval and Apply, and never acquire a fabricated original-paste reference. Each answer is bounded to 1,000 UTF-8 bytes; the existing twelve-support-excerpt and provider-envelope limits still apply. Repeating the same answer does not duplicate its evidence. Capacity exhaustion preserves pending proposals.

Only material ambiguity should prompt a question. Optional missing details, explicit unknowns and approximate dates can remain as given. An insufficient answer must retain unresolved meaning. Explicit corrections may propose an unapproved contact/date/proficiency update; unresolved contradictions remain withheld. These semantic instructions are exercised with controlled responses, not a claim of measured live-provider accuracy.

The browser replaces only the focused claim and remaps operation indexes. Unrelated edited wording and approval survive. A proposal whose supporting claim changed becomes unresolved and needs renewed review. The revised claim's operations start unapproved. Cancellation, stale responses, errors and rephrasing decisions do not apply changes. Rephrasing/attack decisions require changed answer text before another attempt. Original-input edits and Profile revisions retain the existing invalidation rules.

Explicit Apply validates the complete review against its Profile snapshot. Only approved facts and supporting excerpts enter browser-local canonical storage; full pastes, questions and pending answers are not archived. Original excerpts use `professional_information`, and separately elicited answers use `clarification_answer`, even when the wording happens to be identical.
