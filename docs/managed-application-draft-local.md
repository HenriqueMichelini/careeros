## Admission and execution

- The canonical Draft command names the saved full Profile revision, complete original Job Posting, language, selected fact IDs and application-only answers and confirmations. The repository locks and reads the authoritative Profile and supplies approved evidence to the existing workflow. A content-free guard preserves the original Action binding and grant across the shared-ledger and purpose-row commits.
- The signed qualification handoff is optional. The managed qualification route may mint it for a fresh completed connected result after terminal ledger evidence. The proof binds the exact context, original posting, owner, grant, full saved Profile, separate qualification Action/attempt and execution versions. A caller-supplied qualification rerun retains its existing checks and cannot mint a new proof for that supplied context. The Draft validates the proof under current authority before admission and still gates the entire original posting. It retains the proven analysis identity and keyed context digest, while the raw structured qualification result remains transient.
- The Draft graph is the original TypeSafe job gate, OpenAI generation, OpenAI resume support and OpenAI artifact support. The existing resume local guard may record its explicit `not_needed` disposition without a send. A blocked local resume cannot publish a complete Draft. The separate qualification Action shares the same account, global and provider pools.
- Full requests are bounded before each handoff. TypeSafe uses at most 32,000 input tokens. OpenAI uses at most 64,000 per call and 192,000 per attempt, with 8,000, 4,000 and 8,000 output ceilings by stage. The per-reached-stage maximum reservations at those bounds are 1,344, 12,000, 10,000 and 12,000 microUSD. The whole path totals 35,344 microUSD, within the selected 40,000 attempt ceiling. Both maximum attempts total 70,688 within the 80,000 Action ceiling. An unreached stage creates no exposure. Unknown and unsettled evidence remains counted in the existing shared scopes.
- Ten admitted Draft Actions per account/grant and three per rolling 24 hours include failed and canceled Actions. There is one deliberate Retry after the original attempt. A terminal HTTP 429 or 5xx from the original gate or generation can qualify if all reached calls have terminal evidence and every current binding and limit still permits it. An incomplete review, cancellation, lost reply or unknown intent cannot grant Retry. The stable Retry key and purpose witness serialize the one second attempt.
- Each inference attempt has a 25-second maximum. The initial deadline derives from the shared Action's database admission time. Retry uses its own durable start. The HTTP execution budget can shorten those deadlines. The 30-minute customer deadline derives from original admission and can end earlier at a grant or terminal fence.

## Publication and recovery

The existing artifact-support call independently checks required answer correspondence against the complete original posting. It returns an explicit inventory with exact UTF-8 ranges. One supported answer block is required per request. An empty inventory and empty answer field represent no requested answers. Optional suggestions are omitted from the managed complete bundle. The #281 repository seals the same candidate and answer inventory, then atomically publishes the complete version after rechecking current grant, session, source, execution policy, attempt, deadline and terminal reached stages. Generation and review run outside the publication transaction. Incomplete results preserve metadata and leave the complete bundle absent.

The canonical Draft POST, the application endpoint and its Function aliases share this authorization. GET for the opaque creation key and version holds current authorization through the actual response write. The React workspace keeps user-entered work and the connected analysis in memory. Its session storage retains only the account-scoped opaque Draft creation key. Reload uses GET and recovers the exact Action and complete version after a lost reply. A Profile change before confirmed opening closes the undelivered result and removes its cached view. Previously delivered history uses the separate original-grant retrieval window under current read authority.

The generation path writes the restricted Draft and shared Action records. Profile editing, opening, delivery allowance and human Accept use their own authorities. This verification covers the local fake-provider composition.
